Granular (İnce Taneli) Yetki Yapılandırması

{{ generatedSecuritySql }}
Yetim (Orphaned) User Tespiti & Onarımı (Restore Sonrası SID Uyuşmazlığı): 
-- Yetim kullanıcıları tespit et
USE [{{ sec.database }}];
SELECT dp.name AS OrphanedUser, dp.type_desc, dp.create_date 
FROM sys.database_principals dp
LEFT JOIN sys.server_principals sp ON dp.sid = sp.sid
WHERE sp.sid IS NULL AND dp.type IN ('S', 'U', 'G') AND dp.name NOT IN ('guest', 'INFORMATION_SCHEMA', 'sys');

-- Eşleşen login ile SID'yi otomatik onar:
ALTER USER [{{ sec.username }}] WITH LOGIN = [{{ sec.username }}];
GO

DBCC SHRINKFILE & Veri Dosyası Boyutlandırma

Büyük veri silme sonrası disk alanını işletim sistemine geri verin.

DİKKAT: Üretim (Prod) Ortamında Rutin Shrink Yapmayın!

Standart DBCC SHRINKFILE, sayfaları dosyanın sonundan başına taşırken tüm indeksleri aşırı parçalar (index fragmentation %99'a fırlar), devasa işlem günlüğü (LDF) üretir ve disk I/O darboğazı yaratır.

Mümkünse veri taşımayan TRUNCATEONLY tercih edin. Eğer zorunlu hedef boyuta küçülttüyseniz hemen ardından kritik indeksleri REBUILD edin!

DBCC SHRINKFILE T-SQL Komutu 
{{ generatedShrinkSql }}
Dosya İçindeki Boş Alan Yüzdesini Görme: 
USE [{{ shrink.database }}];
SELECT name, size/128.0 AS CurrentSizeMB, 
       size/128.0 - CAST(FILEPROPERTY(name, 'SpaceUsed') AS INT)/128.0 AS FreeSpaceMB,
       ((size/128.0 - CAST(FILEPROPERTY(name, 'SpaceUsed') AS INT)/128.0)/(size/128.0))*100 AS PercentFree
FROM sys.database_files;
GO

Oturum Sonlandırma & Kill Helper

Kilitlenen SPID'leri nazikçe veya zorla sonlandırın, rollback durumunu izleyin.

1. Tekil SPID Sonlandırma & Rollback İzleme

KILL <spid> WITH STATUSONLY: Büyük bir transaction'ı kill ettiğinizde SQL Server veriyi geri almaya (rollback) başlar. Tekrar kill etmek süreci hızlandırmaz! Bu komut rollback'in % kaçının tamamlandığını ve tahmini kalan süreyi gösterir.

2. Veritabanını Tek Kullanıcıya Alma (SINGLE_USER)

Restore, bakım veya isim değişikliği öncesi veritabanına bağlı tüm aktif kullanıcı oturumlarını anında zorla koparır (ROLLBACK IMMEDIATE).

3. Uyuyan & Kilit Tutan Oturumları Topluca Kapatma
SPID {{ killSpid || '' }} Detay Teşhis Sorgusu (Kill Öncesi İnceleme) 
{{ generatedInspectSpidSql }}
Veritabanındaki Tüm Oturumları Dinamik Cursor ile Kapatma Scripti: 
DECLARE @kill varchar(8000) = '';  
SELECT @kill = @kill + 'KILL ' + CONVERT(varchar(5), session_id) + ';'  
FROM sys.dm_exec_sessions
WHERE database_id = DB_ID('{{ killDbTarget }}') AND is_user_process = 1 AND session_id <> @@SPID;
EXEC(@kill);

SQL Server DBA Hızlı Başvuru Kartı (Cheat Sheet)

🛠️ En Sık Kullanılan DBCC Komutları

DBCC CHECKDB ('DBName') WITH NO_INFOMSGS;

Veritabanı bozulmalarını (corruption) ve sayfa tutarlılığını baştan sona denetler.

DBCC SQLPERF(LOGSPACE);

Tüm veritabanlarının Transaction Log boyutunu ve doluluk yüzdesini anlık listeler.

DBCC OPENTRAN('DBName');

Veritabanındaki en eski açık transaction'ı (ve SPID'yi) gösterir; log truncation'ı engelleyen oturumu bulur.

DBCC DROPCLEANBUFFERS; / FREEPROCCACHE;

Test ortamında RAM önbelleğini ve derlenmiş plan önbelleğini temizler (PROD ortamında kesinlikle yapmayın!).
